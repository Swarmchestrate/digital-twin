# Digital Twin Library

A lightweight layer for executing Digital Twin scenarios using the DISSECT-CF-Fog simulator in Swarmchestrate.


## Getting started with DISSECT-CF-Fog

Prerequisites:
- **JDK 17**
- **Apache Maven 3.9**

At the moment, the Maven project is located in the `simulator` directory of the `refactor` branch:

https://github.com/sed-inf-u-szeged/DISSECT-CF-Fog/tree/refactor/simulator

Run the Maven build command in that directory:

```bash
mvn clean package
```

In case of failing tests:

Compile tests, but don't run them:

```bash
mvn clean package -DskipTests
```

Neither compile nor run tests:

```bash
mvn package -Dmaven.test.skip=true
```

After a successful build, the simulator JAR will be created in:

`DISSECT-CF-Fog/simulator/target/dissect-cf-fog-1.0.0-SNAPSHOT-jar-with-dependencies.jar`

**Alternatively, IntelliJ IDEA simplifies the setup with built-in Maven support and integrated JDK management.**


### Running the Simulator Manually

The simulator can also be run directly from the command line for testing purposes. It expects two command-line arguments:

1. Path to a scenario-specific Digital Twin input JSON file generated by the Python library
2. Path to the application data CSV file

```bash
java -cp path/to/simulator.jar \
  hu.u_szeged.inf.fog.simulator.agent.demo.DigitalTwinDemo \
  path/to/dt-input.json \
  path/to/data.csv
```


## Local Testing (CLI)

The Digital Twin engine can be executed locally using the provided CLI interface.

Prerequisites:
- **Python 3.12**
- The simulator JAR must be built separately (see previous section)

Create a virtual environment (optional):

```bash
python -m venv .my_env
source .my_env/bin/activate   # Linux/macOS
.my_env\Scripts\activate      # Windows
```

Run the CLI from the project root directory:

```bash
python -m dt.cli \
  --input path/to/dt-input.json \
  --jar path/to/simulator.jar \
  --data-csv path/to/data.csv \
  --output path/to/output_dir \
  --sort-min metric-name \
  --seed 1234567890 \
  --max-workers 4 \
  --timeout 60 \
  --keep-files
```

`--seed` controls both the deterministic random scenario generation in the Python library and the random behavior of the DISSECT-CF-Fog simulator. The same seed is forwarded to the simulator for every generated scenario.

Use `--sort-min <FIELD>` when lower values are better, or `--sort-max <FIELD>` when higher values are better.

`FIELD` must be the exact name of a numeric metric produced by the simulator in the scenario result JSON.

For example:

```bash
# Noise monitoring
--sort-min "average-E2E-latency_sec"

# Parking monitoring
--sort-min "battery-consumed_percent"
```

`--keep-files` keeps the raw simulator output directories for inspection.

These files are simulator artifacts, not the final Digital Twin result. When `--keep-files` is enabled, cleanup of the final DT result files is the responsibility of the system using the DT library.

Alternatively, install the project in editable mode to run it from anywhere:

```bash
pip install -e .
python -m dt.cli --help
```


## Using Digital Twin as a Library

The Digital Twin engine can also be used as a Python library and integrated into other systems.

Install directly from GitHub:

```bash
pip install git+https://github.com/Swarmchestrate/digital-twin.git
```

Example:

```python
from dt.engine import DtEngine

engine = DtEngine(
    input_path="path/to/dt-input.json",
    jar="path/to/simulator.jar",
    data_csv_path="path/to/data.csv",
    output_path="path/to/output_dir",
    max_workers=4,
    timeout=60,
    keep_files=True,
    sort_field="average-E2E-latency_sec",
    sort_direction="min",
    seed=1234567890,
)

result = engine.evaluate_file()
```

`sort_field` must be the exact name of a numeric metric produced by the simulator.  
`sort_direction` must be either `"min"` or `"max"` depending on whether lower or higher values are preferred.

`evaluate_file()` returns the Digital Twin recommendation and also writes it to `recommendation.json` in the configured output directory.

The returned dictionary can be processed directly by the calling application:

```python
result = engine.evaluate_file()

print("Best scenario:", result["best_scenario"])
print("Best assignment:", result["best_assignment"])

for scenario, value in result["scenario_values"].items():
    print(f"{scenario}: {value}")

if result["failed_scenarios"]:
    print("Failed scenarios:")
    for failed in result["failed_scenarios"]:
        print(failed)
```
